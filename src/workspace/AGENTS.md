# Workspace rules

- Contracts come from an accepted proposal or directly from the lead; `contracts.source` is derived by `ws_contract_guard` from `proposal_id`, never by the app.
- Brief visibility follows `can_see_lead` only; the unassigned "Submitted" queue (`ws_brief_queue`) is GM-only.
- A design version reaches Submitted only via `ws_submit_design_package` (one transaction with the FF&E costing); `ws_design_guard` refuses it unless the lead's costing is exactly Submitted. A Submitted package is re-sent only via `ws_resubmit_design_package` (designer/GM; same completeness bar; notifies GMs and sales), and the designer/GM may edit FF&E while it is Submitted.
- A contract reaches Signed only via `ws_sign_contract(contract, handover)` (one transaction); `ws_contract_guard` refuses others.
- FF&E purchasing band (six buying runs, labels in PRIORITY_BANDS) is defined only by `ws_ffe_band`; item type decides cabinetry/furniture/appliances, the supplier decides online vs pick-up via `ws_ffe_online_supplier` over GM-maintained `ffe_online_retailers` (no client re-band; rows re-derive on next write); names before category, compounds before bare words; bulk re-bands run under `ws.reband` (not marked manual, no sales notice) (trigger `ffe_items_band`); hand changes set `priority_band_manual` and are never recomputed. `ws_ffe_split_parts` splits a compound item per part only when parts differ in band ("Bed + Mattress" stays one row). Unit cost: GM + coordinator on procurement; GM even while Submitted. The categorisation regexes live only in `ws_ffe_kind`, and both `ws_ffe_band` and `ws_ffe_split_parts` read them from there, so a fix goes in one place; `ws_ffe_band` must never gain an overload, because its defaulted `_supplier` makes 3-argument calls ambiguous.
- Brief FF&E jsonb becomes `ffe_items` only via `ws_seed_ffe_from_brief` (called by `ws_assign_brief`, and from the app only through the permission-checked `ws_seed_ffe`; the browser never inserts seed rows); proposals read `ffe_items` only, with no brief fallback.
- Drawing tasks mirror uploads: `ws_sync_drawing_task` (done iff a file of that kind exists AND `in_drive`; un-tick reopens); `tasks_drawing_guard` refuses hand ticks; kinds/hours (24/48/72/72 from `projects.created_at`) only in `ws_drawing_kinds`/`ws_drawing_hours` (mirrored by DRAWING_KINDS; `tasks_drawing_kind_check` uses `ws_drawing_kinds()`); tasks only via `ws_create_drawing_tasks`; `due_at` decides lateness. Designers assigned only by the GM via `ws_assign_lead_designer`/`ws_assign_project_designer`; `ws_project_guard` refuses non-GM changes to designer/coordinator/sales ids.
- A project is created only by `ws_sign_contract` or `ws_convert_lead` (no contract; FF&E may be empty).
- Deal categories: "Signed contract", "Proposal", "Contract" and "Quote" (DEAL_CATEGORIES, mirrored in project_files policies, can_touch_workspace_object); designers/coordinators never touch them. "Signed contract" and "Proposal" project_files are sales/GM deal records; may sit on a lead (deals/<lead_id>/…) and `ws_carry_deal_files` stamps project_id on conversion; only these two may lack a project; drawing triggers skip them.
- Project stage/risk: GM and project coordinator only; overall_pct is derived from stage and proc_pct from ffe_items stages by triggers (no client writes), payments and handover_date only by the GM and sales owner (`ws_project_guard`); the active pipeline is defined only in PROJECT_STAGES, and legacy enum stages are refused on entry.
- Contract value lives only in `project_value_private` (GM + sales owner); `projects.value` is revoked from staff.
- A project with no in-system signed contract (`ws_needs_budget`) buys only after GM budget approval: `ws_submit_budget` (refuses while any item lacks a supplier, per `ws_ffe_gaps`) and `ws_decide_budget` reuse `ffe_costings` states with `purpose = 'budget'` (set only through the `ws.budget` flag).
- Leads are deleted only through the `delete-lead` function: it checks `ws_lead_delete_block` (converted → refused for all; signed contract or not owner → GM-only), removes storage (`ws_lead_storage_paths`) first, then deletes the row as the caller (RLS + `leads_delete_guard`).
- The coordinator sees what to buy and what it costs (ffe_items, ffe_item_costs, suppliers) but nothing the client pays: `ffe_costings.options` has no direct SELECT grant and is read only via `ws_costing_options` (null for coordinators); markup (`ffe_costing_private`), contracts, proposals and project value exclude coordinators.
- Change-request `cost_delta` is client-charged money: no direct SELECT grant, read only via `ws_cr_costs` (empty for coordinators), and `crs_cost_guard` stops coordinators writing it.
- Procurement opens only after the designer (or GM) confirms the converted FF&E list: `projects.confirmed_at/by`, written only via `ws_confirm_ffe_list`/`ws_return_ffe_list` (GM/coordinator)/`ws_submit_budget` under `ws.confirming`; coordinator procurement notices come only from `ws_release_procurement` (confirmed and, where `ws_needs_budget`, budget approved). Confirmed-list edits stay confirmed; coordinators notified on the 15-min debounce.
- An unbuyable item returns to the designer only via `ws_ffe_out_of_stock` → `ws_ffe_reselected` → (`ws_ffe_decide_change` if it costs more); `ffe_items.review*` has no UPDATE grant and `ws_ffe_review_guard` refuses direct writes and ordering stages on held items; confirmed-list changes reach the GM; a raised line total holds the item.
- `ffe_items.internal` is derived from the section name by `ws_ffe_internal_section`/`ffe_items_internal` (no INSERT/UPDATE grant); such rows are excluded from proposal and contract at `useProposalItems` (sole source for both); hidden from sales in the UI; belong to a project.
- Proposal pages group design images by room (renders, then mood-board kind); only room "Mood Board" images feed the trailing mood-board page; a mood-board kind never changes an image's room.
- Workspace orientation content is role-keyed in `GUIDES`; only roles with guide content and explicit `PAGES_BY_ROLE` access receive navigation, so future role guides remain isolated.
- Coordinator deadline tasks are rows in `tasks` carrying `auto_kind`; they are created by `ws_confirm_ffe_list` (24h/72h), `ws_sync_drawing_task` (24h per drawing) and `ws_handover_tasks` (D-3 and D-2 at 18:00 Dubai, rebuilt by the `projects_handover_tasks` trigger when the handover date moves); the partial unique index `tasks_auto_once` makes them idempotent, and `ws_sync_drawing_task` only ticks tasks with `auto_kind IS NULL` so an upload never closes the coordinator's order task.
- Signing a contract re-takes `doc.sections` from the live client-facing FF&E list via `ws_sync_contract_items` (called inside `ws_sign_contract`); it refuses on an empty list rather than wiping the document, and keeps the issued list in `doc.sectionsAtIssue`.
- The coordinator sees design images for their own projects via `ws_coordinator_on_lead` — a SELECT policy on `designs`/`design_images` and the `designs/` branch of `can_touch_workspace_object`; `can_see_lead` itself is deliberately unchanged so proposals, contracts and deal records stay closed to them.
- `projects.on_site_by` overrides the three-day on-site rule per project; `ws_handover_tasks` reads it and the `projects_handover_tasks` trigger watches both date columns, so changing either reschedules the run.
- Building/site material is forced to band 5 in `ws_ffe_band` via `ws_ffe_internal_section` before any kind test; the site run is wallwork → delivered → handyman + wallpaper → operations + qc, spaced a day apart from the on-site date and capped at handover − 1.
