# Workspace architecture rules

- Contracts have two routes (accepted proposal, or direct from the lead); `contracts.source` is derived by `ws_contract_guard` from `proposal_id`, never by the app.
- Brief visibility follows `can_see_lead` only; the unassigned "Submitted" queue (`ws_brief_queue`) is GM-only.
- A design version reaches Submitted only via `ws_submit_design_package` (one transaction with the FF&E costing); `ws_design_guard` refuses it unless the lead's costing is exactly Submitted.
- A contract reaches Signed only via `ws_sign_contract(contract, handover)` (one transaction: project, lead Won, FF&E stamped, drawing tasks, notices); `ws_contract_guard` refuses any other path.
- FF&E purchasing band (1 Cabinetry → 5 Kitchenware & linen, labels in PRIORITY_BANDS) is defined only by `ws_ffe_band`, matching item names before category with compounds before bare words; bulk re-bands run under `ws.reband` so they neither mark rows manual nor notify sales (trigger `ffe_items_band`); hand changes set `priority_band_manual` and are never recomputed. A compound item is split into one row per part by `ws_ffe_split_parts` only when its parts fall in different bands ("Bed + Mattress" stays one row). Unit cost is editable by the GM and coordinator on the procurement list, and by the GM even while the costing is Submitted.
- Brief FF&E jsonb becomes `ffe_items` only via `ws_seed_ffe_from_brief` (called by `ws_assign_brief`, and from the app only through the permission-checked `ws_seed_ffe`; the browser never inserts seed rows); proposals read `ffe_items` only, with no brief fallback.
- Drawing tasks mirror uploads: `ws_drawing_changed` on project_files calls `ws_sync_drawing_task` (done iff a file of that kind exists) and `tasks_drawing_guard` refuses hand ticks; kinds/deadlines only in `ws_drawing_kinds`/`ws_drawing_hours` (mirrored by DRAWING_KINDS), tasks are created only via `ws_create_drawing_tasks`, and `tasks.due_at` decides lateness (`due_date` derived from it).
- A project is created only by `ws_sign_contract` (contract route) or `ws_convert_lead` (no contract; may have an empty FF&E list).
- Deal categories: "Signed contract", "Proposal", "Contract" and "Quote" (DEAL_CATEGORIES, mirrored in the project_files policies and can_touch_workspace_object); designers and coordinators can never read or upload any of them. "Signed contract" and "Proposal" project_files are sales/GM-upload deal records; older files are kept as versions; they may be filed on a lead (lead_id, path deals/<lead_id>/…) and `ws_carry_deal_files` stamps project_id on conversion; only these two may lack a project; drawing triggers ignore them.
- Project stage/risk: GM and project coordinator only; overall_pct is derived from stage and proc_pct from ffe_items stages by triggers (no client writes), payments and handover_date only by the GM and sales owner (`ws_project_guard`); the active pipeline is defined only in PROJECT_STAGES, and legacy enum stages are refused on entry.
- Contract value lives only in `project_value_private` (GM + sales owner); `projects.value` is revoked from staff.
- A project with no in-system signed contract (`ws_needs_budget`) buys only after GM budget approval: `ws_submit_budget` (refuses while any item lacks a supplier or purchase link, per `ws_ffe_gaps`) and `ws_decide_budget` reuse `ffe_costings` states with `purpose = 'budget'` (set only through the `ws.budget` flag).
- Leads are deleted only through the `delete-lead` function: it checks `ws_lead_delete_block` (converted → refused for all; signed contract or not owner → GM-only), removes storage (`ws_lead_storage_paths`) first, then deletes the row as the caller (RLS + `leads_delete_guard`).
- The coordinator sees what to buy and what it costs (ffe_items, ffe_item_costs, suppliers) but nothing the client pays: `ffe_costings.options` has no direct SELECT grant and is read only via `ws_costing_options` (null for coordinators); markup (`ffe_costing_private`), contracts, proposals and project value exclude coordinators.
- Change-request `cost_delta` is client-charged money: no direct SELECT grant, read only via `ws_cr_costs` (empty for coordinators), and `crs_cost_guard` stops coordinators writing it.
- Procurement opens only after the designer (or GM; GM when no designer) confirms the converted FF&E list: `projects.confirmed_at/by`, written only via `ws_confirm_ffe_list`/`ws_return_ffe_list` (GM or coordinator)/`ws_submit_budget` under the `ws.confirming` flag; coordinator procurement notices come only from `ws_release_procurement` (confirmed and, where `ws_needs_budget`, budget approved). Edits to a confirmed list keep it confirmed and notify coordinators on the 15-minute debounce.
- An item the coordinator can't buy returns to the designer only via `ws_ffe_out_of_stock` → `ws_ffe_reselected` → (`ws_ffe_decide_change` if the replacement costs more); `ffe_items.review*` has no UPDATE grant and `ws_ffe_review_guard` refuses direct writes and ordering stages on held items; every confirmed-list change reaches the GM, and a raised line total holds the item for approval.
